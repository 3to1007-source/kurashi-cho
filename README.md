# 暮らし帳 (kurashi-cho)

家計簿・健康管理・カレンダーを1つにまとめた、夫婦2人で使う家計アプリのプロトタイプ。
「別々のアプリに分かれているから続かない」を解くため、**家計・からだ・予定の3つの記録を同じ日付の上で一覧できること**を中心の価値にしている。

SPAとして動き、すべてのデータは端末の `localStorage` に暗号化して保存する。Supabase(無料枠のPostgreSQL)を設定すると、同じ帳面を複数の端末から開けるようになる。**未設定でも今まで通りローカルのみで動く**(設定は任意)。

## 起動方法

```bash
npm install
npm run dev
```

`npm run build` でビルド、`npm run preview` でビルド結果の確認ができる。

複数端末で使いたい場合は下の「複数端末で使う(Supabase連携)」を参照。

## 技術構成

- React 18 + Vite(JavaScript、状態管理ライブラリなし)
- スタイルはCSS Modules(Tailwind不使用)
- データ保存は `localStorage`(キー: `kurashicho:vault`)+ 任意でSupabase(`vaults`テーブル)
- 暗号化は Web Crypto API(`crypto.subtle`)のみ。外部の暗号ライブラリは使用していない

## 設計の要点

### 認証 = 暗号化(パスワード照合ではない)

クライアントだけで完結するアプリなので「パスワードが正しいかどうかを照合する」という発想自体が意味を持たない。
代わりに、**データを開けるかどうか**でパスワードの正しさを判定する封筒方式(envelope encryption)を採用している。

1. データ暗号鍵(DEK)を1本だけ生成する(AES-GCM 256bit)
2. 各ユーザーのパスワードから鍵暗号鍵(KEK)を導出する(PBKDF2-SHA256, salt 16byte, 600,000回)
3. DEKをKEKで `wrapKey` して保存する(IVは12byte乱数)
4. データ本体はDEKで暗号化して保存する

これにより、夫と妻はそれぞれ別のパスワードで同じデータを開ける。家族を追加するときは、ログイン中にメモリ上にあるDEKを新しいパスワードのKEKで包み直して `users` に追加するだけで済む。

保管庫(vault)には**暗号文とソルトしか入らない**。パスワードもハッシュも保存しない。

```json
{
  "v": 1,
  "users": [
    { "id": "kazusa", "salt": "b64", "iter": 600000, "wrapIv": "b64", "wrapped": "b64" }
  ],
  "iv": "b64",
  "data": "b64",
  "updatedAt": 1700000000000,
  "updatedBy": "kazusa"
}
```

ログイン処理は、IDでユーザーを引き、入力されたパスワードからKEKを導出して `unwrapKey` を試みる。失敗すればパスワードが違うと判断する。**ID不在とパスワード誤りは同じエラー文言**にして、IDの存在を漏らさないようにしている。

その他のセキュリティ関連の実装:

- 無操作10分で自動ロック(`click` / `keydown` / `touchstart` / `scroll` でタイマーをリセット)
- ログイン5回失敗で30秒待機
- 初期設定時に「パスワードは保存されないため、忘れると復旧できない」旨の同意チェックを必須化
- パスワードは8文字以上、強度メーターを表示
- DEKはReactのstate上にのみ保持し、ロック時にnullへ

**この端末を覚えておく機能**: ログインに成功すると、DEKを端末ごとのランダムな鍵(人が覚えるパスワードではない)で包み直して`localStorage`に保存する。これにより、次回このブラウザでアプリを開いたとき(ページ更新時なども含む)はパスワード入力なしでそのまま開く。無操作10分の自動ロック、または設定シートの「帳面を閉じる」を押すと、この端末の記憶は破棄され、次回は改めてパスワードが必要になる。端末そのもの(ブラウザのlocalStorageへのアクセス)が実質的な鍵になる設計のため、共有端末や紛失の可能性がある端末では、使い終わったら都度「帳面を閉じる」を押すことを推奨する。

### 画面構成

- **家計**: 「今月家計で使えるお金」(予定収入=給料などと先取り支出=家賃・光熱費などをそれぞれリスト化しておき、実際の入出金記録を待たずに開始日のタイミングで差し引いて残金を出す。金額はどちらも毎月編集可能)、「使えるお金」(家計の収入とは別枠、ユーザーごとに開始日・締日・月額を設定できるお小遣い制の予算。締日までの未来日付の支出も先取りで差し引いて「今月あと◯◯円」を表示)、カテゴリ予算(食費・交際費など分類ごとの月の予算。誰の記録でも合算して残額を表示)、月次の収入・支出・差引サマリー、支出カテゴリ別の横棒グラフ、記録フォーム(支出時はレシート撮影→OCRで金額・日付を自動入力できる。ブラウザ内で完結し画像はどこにも送信されない)、当月の記録一覧
- **からだ**: 体重・睡眠・歩数をユーザーごとに分離して記録。当月平均と体重の推移(SVG自前描画の折れ線グラフ)
- **予定**: 月カレンダー(各日に家計=赤・からだ=緑・予定=青・予定収入や先取り支出の日=山吹のドット表示)。日をタップすると「その日の帳」として記録を縦に並べて表示する、このアプリの中心機能。先取り支出に支払い日を設定すると土日祝を避けて自動的に翌営業日にずらし、予定収入(給料日)に受取日を設定すると土日祝を避けて自動的に前営業日にずらしてカレンダーに表示する(日本の祝日は振替休日・国民の休日を含む近似計算)
- **試算**: 給与所得控除・所得税速算表に基づく税額試算、ふるさと納税上限額(朱色の判子風表示)、NISA積立シミュレーション

設定は2系統に分かれている。ヘッダー右上の⚙(全タブ共通)からはカイゼンメモ(改善案ToDo)、家族の追加、他の端末との共有、保管庫の再読込、データのJSON書き出し、帳面を閉じる(ロック)を扱う。家計タブのみヘッダー左上に☰が表示され、先取り支出・使えるお金・カテゴリ予算という3つの予算設定はそちらにまとめている(メニュー→各設定画面という2階層で、どちらのシートにも明示的な「閉じる」ボタンがある)。

### 税計算について

給与所得控除・所得税速算表・住民税所得割・ふるさと納税上限・NISAの複利計算はすべて `src/lib/tax.js` に実装している。**表示される金額はすべて概算・目安であり、実際の税額は税理士や公式シミュレーターで確認する必要がある**旨を画面上に明記している。

### 複数端末での同期(帳面ID)

Supabaseを設定すると、暗号化済みのvault(封筒方式でラップした鍵と暗号文)を1行(`id = 帳面ID`)としてクラウドに保存する。**サーバーが受け取るのは暗号文だけ**で、平文データやパスワードは一切送らない。帳面IDそのものは推測困難な12文字のランダム文字列で、実質的に「知っている人だけが辿り着ける」共有リンクのように機能する(内容の秘匿は引き続き暗号化が担う)。

- 新しい帳面を作ると帳面IDが発行される。もう一方の端末では「すでにある帳面をこの端末でも開く」から、帳面ID・ID・パスワードを入力して同じ帳面を開ける
- 保存するたびにクラウドへ送信し、帳面を開いた瞬間・「最新に更新」を押した瞬間・他の端末からの更新をリアルタイム受信した瞬間に、**新しい方(`updatedAt`)を採用する「後勝ち」**でローカルへ取り込む
- 通信できない/未設定のときは自動的にローカルのみで動作し、データが失われることはない

### レシートOCR

家計タブの記録フォーム(支出時)に「レシートを撮影して金額を読み取る」ボタンがある。Tesseract.js(WASM版Tesseract OCR)を使い、**画像はブラウザ内で処理されどこにも送信されない**。初回利用時のみ、認識エンジン本体(OCRのコアとその後日本語データ)をjsdelivr CDNから読み込む(数MB、以降はブラウザにキャッシュされる)。

- 「合計」「お会計」などのキーワード行、なければ文中でいちばん大きい金額らしき数字を金額として読み取る
- 日付らしき記載があれば日付欄にも反映する
- サーマル紙のレシートや小さい文字は読み取り精度が高くないため、**読み取り結果は必ず利用者が確認し、記録する前に修正できる**ようにしている(自動送信はしない)

### やっていないこと(意図的)

- 銀行口座との自動連携(残高・入出金の参照)は実装しない。銀行法上の「電子決済等代行業(参照型)」に該当し、登録なしには行えないため。当面は手入力とCSV取込のみを想定。
- 投資の試算は一般的な計算ツールにとどめ、個別の金融商品の推奨は行わない(金融商品取引法の投資助言業に抵触するため)。

```
src/
  lib/          crypto.js(暗号化) / vault.js(保管庫の読み書き・同期) / remote.js(Supabase連携) / tax.js(税計算) / allowance.js(予算計算) / holidays.js(日本の祝日判定) / receiptOcr.js(レシートOCR) / constants.js / format.js / useIdleTimer.js
  context/      AppContext(DEK・データ・ログインユーザー・同期状態の共有)
  components/
    auth/       Boot / Setup / Login / Join(帳面IDで別端末から開く)
    layout/     Shell / Header / TabBar / SettingsSheet
    kakei/      家計タブ
    karada/     からだタブ
    yotei/      予定タブ(月カレンダー・その日の帳)
    shisan/     試算タブ(税額試算・NISA)
    common/     共通コンポーネント(パスワード強度メーターなど)
supabase/
  schema.sql    Supabase側に作るテーブルとRLSポリシー
.github/workflows/
  deploy.yml    GitHub Pagesへの自動デプロイ
```

## 複数端末で使う(Supabase連携)

無料のSupabaseプロジェクトを1つ作るだけで、夫婦それぞれの端末から同じ帳面を開けるようになる。

### 1. Supabaseプロジェクトを作る

1. https://supabase.com で無料アカウントを作り、新しいプロジェクトを作成する
2. プロジェクトのSQL Editorを開き、このリポジトリの `supabase/schema.sql` の内容をそのまま実行する
3. Settings → API から「Project URL」と「anon public」キーを控える

### 2. ローカルで試す場合

リポジトリ直下に `.env` を作り、`.env.example` を参考に2つの値を貼り付けて `npm run dev` を再起動する。

### 3. それぞれのスマホ・PCから使えるようにする(GitHub Pages)

このリポジトリには `main` へのpushで自動的にGitHub Pagesへデプロイするワークフロー(`.github/workflows/deploy.yml`)が入っている。有効にする手順:

1. GitHubリポジトリの Settings → Secrets and variables → Actions で、`VITE_SUPABASE_URL` と `VITE_SUPABASE_ANON_KEY` を Repository secrets として追加する
2. Settings → Pages で、Source を「GitHub Actions」に切り替える(初回のみの手動操作)
3. `main` にpushすると自動でビルド・デプロイされ、`https://<GitHubユーザー名>.github.io/kurashi-cho/` で夫婦それぞれの端末からアクセスできるようになる

### 4. 実際に2台をつなぐ

1. 1台目で帳面を新規作成すると「帳面ID」とQRコードが表示される(あとから設定シート「他の端末と共有」でも確認できる)
2. 1台目の設定シート「家族を追加」でもう1人のID・パスワードを登録する
3. 2台目のカメラ(標準のカメラアプリでよい)でそのQRコードを読み取る。帳面IDが自動入力された状態でこのアプリが開くので、2人目のID・パスワードだけ入力すればよい(QRコードにはパスワードを含めていないため、読み取られても中身は開けない)。QRコードが読み取れない場合は「すでにある帳面をこの端末でも開く」から帳面IDを手入力する
