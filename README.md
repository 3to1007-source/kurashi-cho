# 暮らし帳 (kurashi-cho)

家計簿・健康管理・カレンダーを1つにまとめた、夫婦2人で使う家計アプリのプロトタイプ。
「別々のアプリに分かれているから続かない」を解くため、**家計・からだ・予定の3つの記録を同じ日付の上で一覧できること**を中心の価値にしている。

現段階はローカルで完結するSPA。バックエンドは持たず、すべてのデータは端末の `localStorage` に暗号化して保存する。

## 起動方法

```bash
npm install
npm run dev
```

`npm run build` でビルド、`npm run preview` でビルド結果の確認ができる。

## 技術構成

- React 18 + Vite(JavaScript、状態管理ライブラリなし)
- スタイルはCSS Modules(Tailwind不使用)
- データ保存は `localStorage`(キー: `kurashicho:vault`)
- 暗号化は Web Crypto API(`crypto.subtle`)のみ。外部の暗号ライブラリは使用していない

## 設計の要点

### 認証 = 暗号化(パスワード照合ではない)

クライアントだけで完結するアプリなので「パスワードが正しいかどうかを照合する」という発想自体が意味を持たない。
代わりに、**データを開けるかどうか**でパスワードの正しさを判定する封筒方式(envelope encryption)を採用している。

1. データ暗号鍵(DEK)を1本だけ生成する(AES-GCM 256bit)
2. 各ユーザーのパスワードから鍵暗号鍵(KEK)を導出する(PBKDF2-SHA256, salt 16byte, 600,000回)
3. DEKをKEKで `wrapKey` して保存する(IVは12byte乱数)
4. データ本体はDEKで暗号化して保存する

これにより、夫と妻はそれぞれ別のパスワードで同じデータを開ける。家族を追加するときは、ログイン中にメモリ上にあるDEKを新しいパスワードのKEKで包み直して `users` に追加するだけで済む。

保管庫(vault)には**暗号文とソルトしか入らない**。パスワードもハッシュも保存しない。

```json
{
  "v": 1,
  "users": [
    { "id": "kazusa", "salt": "b64", "iter": 600000, "wrapIv": "b64", "wrapped": "b64" }
  ],
  "iv": "b64",
  "data": "b64",
  "updatedAt": 1700000000000,
  "updatedBy": "kazusa"
}
```

ログイン処理は、IDでユーザーを引き、入力されたパスワードからKEKを導出して `unwrapKey` を試みる。失敗すればパスワードが違うと判断する。**ID不在とパスワード誤りは同じエラー文言**にして、IDの存在を漏らさないようにしている。

その他のセキュリティ関連の実装:

- 無操作10分で自動ロック(`click` / `keydown` / `touchstart` / `scroll` でタイマーをリセット)
- ログイン5回失敗で30秒待機
- 初期設定時に「パスワードは保存されないため、忘れると復旧できない」旨の同意チェックを必須化
- パスワードは8文字以上、強度メーターを表示
- DEKはReactのstate上にのみ保持し、ロック時にnullへ

### 画面構成

- **家計**: 月次の収入・支出・差引サマリー、支出カテゴリ別の横棒グラフ、記録フォーム、当月の記録一覧
- **からだ**: 体重・睡眠・歩数をユーザーごとに分離して記録。当月平均と体重の推移(SVG自前描画の折れ線グラフ)
- **予定**: 月カレンダー(各日に家計=赤・からだ=緑・予定=青のドット表示)。日をタップすると「その日の帳」として3種の記録を縦に並べて表示する、このアプリの中心機能
- **試算**: 給与所得控除・所得税速算表に基づく税額試算、ふるさと納税上限額(朱色の判子風表示)、NISA積立シミュレーション

設定シート(ヘッダー右上から開くボトムシート)には、カイゼンメモ(改善案ToDo)、家族の追加、保管庫の再読込、データのJSON書き出し、帳面を閉じる(ロック)機能がある。

### 税計算について

給与所得控除・所得税速算表・住民税所得割・ふるさと納税上限・NISAの複利計算はすべて `src/lib/tax.js` に実装している。**表示される金額はすべて概算・目安であり、実際の税額は税理士や公式シミュレーターで確認する必要がある**旨を画面上に明記している。

### やっていないこと(意図的)

- 銀行口座との自動連携(残高・入出金の参照)は実装しない。銀行法上の「電子決済等代行業(参照型)」に該当し、登録なしには行えないため。当面は手入力とCSV取込のみを想定。
- 投資の試算は一般的な計算ツールにとどめ、個別の金融商品の推奨は行わない(金融商品取引法の投資助言業に抵触するため)。

## ディレクトリ構成

```
src/
  lib/          crypto.js(暗号化) / vault.js(保管庫の読み書き) / tax.js(税計算) / constants.js / format.js / useIdleTimer.js
  context/      AppContext(DEK・データ・ログインユーザーの共有)
  components/
    auth/       Boot / Setup / Login
    layout/     Shell / Header / TabBar / SettingsSheet
    kakei/      家計タブ
    karada/     からだタブ
    yotei/      予定タブ(月カレンダー・その日の帳)
    shisan/     試算タブ(税額試算・NISA)
    common/     共通コンポーネント(パスワード強度メーターなど)
```
